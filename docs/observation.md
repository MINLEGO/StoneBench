# Observation contract (issue #7)

Minecraft 1.21.11 remains the authority. No sprint is enabled: `advance` uses the established vanilla unit step, 1..6000 ticks. Its default `diff` compares the complete observed fields at operation start/end (blocks, typed NBT, runtime memory, inventories and deferred queues). `modify_blocks` also reports this diff. A component that changes and returns may have no final state diff; request `trace: true` to recover its intermediate end-of-tick states.

```json
{"name":"advance","arguments":{"ticks":12,"trace":true}}
{"name":"read_region","arguments":{"min":{"x":1056,"y":79,"z":1056},"max":{"x":1087,"y":80,"z":1063}}}
{"name":"read_artifact","arguments":{"artifact_id":"<returned UUID>","offset":0,"limit":29}}
{"name":"compare_traces","arguments":{"left":"<trace UUID>","right":"<trace UUID>"}}
```

`read_region` returns every coordinate in inclusive ordered bounds, air included. It prepares newly requested chunks while frozen and inserts no world tick. A request above one million coordinates is explicitly rejected; split it into regions. This resource bound is not a construction/conformity boundary. `read_blocks` keeps its compatible bounded 1..256 coordinate response and now includes typed block-entity NBT/runtime fields.

Region blocks, snapshot blocks, diffs, traces, divergent fields and intra-tick events are immutable JSONL artifacts under `stonebench/artifacts/<UUID>.jsonl`. References provide `artifact_id`, `kind`, `count`, `bytes`, `sha256` and `complete`. Descriptors are persisted alongside the data as `.jsonl.meta`; they can be reloaded after process restart. `read_artifact` takes a required `offset` and `limit` (1..256), returns `entries`, total descriptor, `next_offset` (null at end) and page `complete`. Iterate until null and require exactly `count` entries. The full-file SHA-256 and expected page length are verified on retrieval; alteration/truncation is an infrastructure error, never a successful partial page. No entry or nested value is silently capped. Page entry count is bounded, not the size of an individual NBT/observation entry. Preserve these artifacts with diagnostic results; the MCP response is a reference, not the data itself.

`advance(trace=true)` returns `trace` with `expected_ticks`, `start_world_time`, `start_simulation_index`, and `continuity`. A successful uninterrupted N-tick trace has N entries. Each contains 1-based operation `tick_index`, absolute useful `simulation_index`, `phase=end_tick`, absolute `world_time`, `time_of_day`, `complete`, `state` and `events`. Endpoints are separate `initial`/`final` observations. Their snapshots refer to paginated block artifacts; block/fluid queues and pending block events are retained in the state. Infrastructure failure preserves the executed samples and requested count; missing ticks or lost coverage make continuity explicitly incomplete. A later read cannot heal observations already missed.

Intra-tick events have per-tick `order`, full-operation `operation_order`, tick/simulation indexes, simulation phase, absolute clocks, position and exact detail. Hooks observe block-state reads (including signal source queries), requested/effective block writes, neighbor update targets, schedule requests (with absolute deadline, priority and sub-tick order), scheduled callbacks, enqueue requests and actual matching block-event callbacks. A schedule/enqueue request is labelled as a request: vanilla can deduplicate or reject it. Pending block events preserve vanilla insertion order, type and data. Runtime block/fluid queues are sorted by vanilla deadline, priority and sub-tick order, retaining all three fields. End-of-tick capture occurs after world processing on the server thread; no asynchronous view is mixed into a snapshot.

NBT is `{type:<vanilla numeric tag id>,value:...}`. Compound keys alone are sorted. Lists preserve all elements and their order. Scalars/typed arrays retain vanilla SNBT strings; this preserves exact longs beyond JSON's floating-point range, byte/int/long distinctions, float/double suffixes and array ordering. NBT inventories and temporal fields are retained, alongside compatible occupied-slot inventory records. Moving pistons include serialized pushed state/facing/source/extending/last-progress and typed runtime `progress`, `last_progress`, `saved_world_time`. Hoppers include serialized transfer cooldown and typed runtime `last_tick_time`/`transfer_cooldown`. Observing hopper memory is not proof of faithful restoration or rest: its known behavioral uncertainty remains for the checkpoint/transition work.

The influence set grows from placements and their neighbors, requested region/coordinate reads, runtime deferred queues, vanilla reads/writes and neighbor/event targets, including temporary piston locations. It is not clipped to the prototype rectangle. An observed position outside prepared chunks is retained in `coverage.outside_prepared_chunks`, makes coverage `insufficient` and subsequent samples incomplete. Lost chunk readiness also makes coverage insufficient. Coverage explicitly reports `certification=false`: this instrumentation covers the listed fields/hooks, not all JVM memory, entities, random generators or universal influence completeness. Each block entity states its runtime coverage. Unsupported or uninstrumented components cannot acquire a positive conformity verdict from an identical serialized snapshot. Downstream transition/checkpoint/verifier tools must inspect coverage/runtime limits and retain an indeterminate result when they lack evidence.

`compare_traces` resolves block/event artifact references and compares exact states, events, clocks, indexes and ordered lists. It independently reports continuity and the first differing tick/fields; fields are paginated. Different absolute clocks remain different. An identical partial/incomplete trace returns `incomplete`, never `equal`. The Java comparison helper also supports complete in-memory observations for downstream replay diagnostics. This observation API does not implement checkpoints, rest detection, input adapters or conformity.

Focused checks run during `scripts/build.ps1` through `observationChecks` (assertion runner with no extra test framework). `tests/observation.py` exercises real MCP SDK 1.26.0 against disposable servers. See `docs/evidence/issue-7/README.md` for executed fixtures, hashes, commands and limits.
