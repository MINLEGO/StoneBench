# Eight-task alpha campaign preparation (#15)

The launcher runs regular DOOR 2×2, 3×3, 4×4 and 5×5 separately for `minimize_volume` and `minimize_opening_ticks`. The existing task supplies integer origin (1024,80,1024), horizontal +X, vertical +Y, normal +Z and immutable closed-door frame positions. Each task starts in a fresh flat air world. The agent builds the physical enclosure; no pattern or extra category constraint is introduced. The initial prepared observation region is not a construction/conformity boundary. The delivered frozen rule table and checkpoint/protocol/measurement contracts remain authoritative.

`python -m app.campaign.launch plan` prints the nonsecret numerical proposal and its SHA-256. `rehearsal --output <new-directory>` uses Inspect's native ReAct and scripted ModelAPI against eight actual fresh Minecraft/MCP attempts. Each leaves a chest inventory, advanced clocks, declared input and an incomplete checkpoint; the next startup checks air at every frame and residue position, no inventory, queues/events, input or checkpoints. Fresh clocks equal only the explicitly reported initial preparation ticks; useful simulation is zero. Initial chunk preparation may take a varying number of real ticks, retained separately without normalization. The last task deliberately produces no submission. This is a lifecycle/isolation rehearsal, not a model solving result or provider calibration.

The launcher invokes the existing supervisor/lifecycle script with `-ProductionServer -ServerCount 1`; test-only tools must be absent. One independent working world is used per task. Work MCP/game defaults 19765/26581; independent verifier copies 19767..19768/26583..26584. The original test script keeps two servers by default for existing suites. Attempts are sequential, ports are reused only after owned children stop. Existing native sprint acceleration is the default. No artificial 20 TPS cap, global verification wall quota or additional tick quota is introduced: transitions remain 36000gt and derived verification maximum 432000gt; phase watchdogs and heartbeat remain separate.

Each task retains exact task, MCP schema catalogue and hash, effective environment, initial/reset snapshot, native Inspect logs, full retained tool results, local events, usage, selected checkpoint or `no_submission`, score report, failed/incomplete diagnostics, checkpoints, journals, traces and world files. The campaign archives frozen source and controller JAR, prompt/config/plan/hash, versions, runtime paths and deployed settings. Per-file payload hashes are read back from the archive. Immutable copied libraries/cache trees are excluded, rather than secret-containing arbitrary parent runtime trees. Exact measurements remain separate: nullable volume with lower/upper envelopes and gaps, opening, closing and rest timestamps. No fused score or record claim is generated.

## Provisional numerical plan and authorization gate

Model: `xiaomi/mimo-v2.6-flash`, through OpenRouter. Exact endpoint order/allowlist: `makora/fp8`, then `xiaomi/fp8`, quantization fp8, `allow_fallbacks=false`: the two explicitly ordered endpoints may be tried; no unlisted provider may be used. Price snapshot: Makora input $0.13/M, Xiaomi input $0.14/M, both completion $0.28/M. No cache saving assumed. Reasoning is explicitly enabled through `reasoning: {enabled: true}` in both calibration and campaign; no unsupported effort or reasoning.max_tokens is inferred, and reasoning is not excluded. Reasoning belongs to completion usage and is never billed twice by the ledger. `require_parameters=true` is omitted because both endpoint parameter lists omit `parallel_tool_calls`, while Inspect sends false; the local tool execution guard still serializes calls. Calibration must verify actual endpoint acceptance.

Each of eight attempts gets 2,000,000 total observed tokens. Construction request completion bound: 32,768; final visible allowance 8,192 plus reasoning allowance 57,344 = final request completion bound 65,536; safety margin 32,768. Final reserve is recalculated as actual serialized context UTF-8 bytes plus 65,536 + 32,768 before every generation. A client byte guard stops before a request above 524,288 bytes. This is a conservative text heuristic, not tokenizer/hidden-overhead proof. Up to eight finalization calls are allowed while usage remains known. Campaign execution stops after the first missing-usage response, retaining a nullable total and checkpoint choice/absence; it never spends eight more unknown calls. The standalone #14 harness retains its original finite fallback. Forecast alone does not guarantee eight full completion calls fit the reserve.

At 80% input and 20% completion, $0.320/attempt or $2.56 total on Makora; $0.336/attempt or $2.688 total on Xiaomi. Worst split within the nominal observed 16M campaign tokens: $4.48 total ($0.56/attempt). These are forecasts, not monetary caps: an already running call, hidden input overhead or a provider max_tokens violation can exceed total. Inspect generation retries, sample retries and OpenAI SDK HTTP retries are all disabled. Cached usage/cost/reasoning fields remain null when absent; raw OpenRouter `usage.cost` is retained separately from Inspect's model-level computed cost, which is not route-exact. Response IDs, raw usage and selected routing metadata are retained; unavailable route identity remains unavailable. The only recorded extra header is nonsecret `X-OpenRouter-Metadata: enabled`.

Before the eight paid attempts, authorize **calibration separately**: one fresh 2×2-volume world, at most two native calls, read-only finalization guard from the first call, same discovered schemas/prompt/config and explicit reasoning enabled, 400,000 total observed tokens and 65,536 completion bound per call. Nominal forecast at completion price: $0.112. Under the same deliberately loose one-in-flight excess bound of 1,114,112 tokens, the conditional calibration bound is (400,000 +1,114,112) ×$0.28/M = $0.42395136 (about $0.424), not an enforced USD cap. The next user authorization covers only this calibration; the eight-task campaign requires a later decision using its actual results. Compare context byte estimates with actual input usage; verify response routing identity, completion/reasoning availability, reported cost/cache, stop reason and max_tokens adherence. A length stop with no visible response or tool call fails calibration, including when reasoning consumes the whole completion budget; the eight tasks remain blocked pending adjustment. This does not calibrate solving performance. Calibration may require adjusting the frozen numerical plan and reauthorization before the campaign.

If usage is available and the provider honors its limits, a deliberately loose extra one-in-flight bound of 1,048,576 context +65,536 completion =1,114,112 tokens per attempt adds $2.49561088 across eight attempts. Conditional campaign bound: $6.97561088. Including calibration with its own one-in-flight excess yields $7.39956224 (about $7.40) for both stages. The former $7.08761088 combines campaign excess with nominal calibration only and is not a global ceiling. This overcounts any model context limit that already includes completion, and is not an enforced USD cap. The client byte guard is tighter but hidden tokenizer/template overhead still requires provider calibration. A limit breach or unavailable usage invalidates the monetary bound; stop and retain diagnostics.

Paid commands refuse to run without a local authorization JSON that root creates only after explicit user approval, naming this exact `plan_sha256`, `scope` (`calibration` or `paid`) and `authorized_by_user: true`. Calibration authorization never unlocks `paid`. Paid launch additionally requires an accepted calibration `status.json` for the same plan; raw provider identity, real cost, available usage and completion/context checks must pass. A missing/unexpected route or unavailable usage stops later paid tasks. Generation metadata is read through OpenRouter's authenticated generation endpoint after completed inference; these reads create no additional inference. No authorization or key is created by preparation. The only key loader reads the primary gitignored `.runtime/openrouter.env` locally into the inference process environment, returns only boolean presence and never places authentication in recorded model args. Ambient keys are stripped before server/lifecycle launch. The secret file is not copied to a worktree, source snapshot or archive.
