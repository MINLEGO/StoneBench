# Geometry tools (issue #11)

`describe_rules` returns the frozen, paraphrased source table and measurement handoff. `check_geometry` takes `expected_state: open|closed`; optional `frame_min_z` and `frame_max_z` describe contiguous door frame layer(s) including the immutable task plane (currently z=1024). Omit both for the task plane. This default is a diagnostic choice for a single-layer fixture, not a community requirement of depth one. Shifted passage, user-supplied input evidence and arbitrary exclusion lists are rejected.

The controller prepares the frame/perimeter positions before calling `RegularDoorGeometry.check(world, task, args, Inputs.declared())`. It observes the live server world, the full tracked influence set and entities within its bounds. No world tick is advanced. Coordinate roles in `measurement_roles` identify frame interior and physical encadrement, with conditional exclusion reasons; they do not measure volume or prove circuit irrelevance. Perimeter corners do not seal a passage side and are not mandatory or automatically excluded as frame.

Every diagnostic keeps source index, expected behavior, observed coordinates, coverage and status. A frozen frame pattern can satisfy individual geometry criteria while stability, clock necessity and temporal coverage remain indeterminate. `geometry_status` aggregates all mandatory criteria, so it remains indeterminate until the functional protocol supplies those additional proofs. `conforms_to_alpha=false` means this standalone snapshot is not an alpha protocol result. Issue #12 must compose its bounded rest/cycle/input/coverage evidence with these individual diagnostics. It must retain mandatory unresolved diagnostics, and may not turn an unsupported component or infrastructure failure into a geometric fault.

A non-quartz block can satisfy necessary physical properties yet still require evidence that quartz substitution preserves functioning. Quartz blocks satisfy this condition by identity. This is an explicit evidence gap, not a blanket prohibition of other materials. The checker accepts non-quartz enclosure walls and non-air, noncolliding hallway contents when the requested plain regular DOOR has no SUPER/FULL SEAMLESS composition restriction. Canonical full inward collision faces, including piston-head plates, bound the passage; other partial shapes remain indeterminate pending traversal evidence.

The real MCP fixture in `tests/geometry.py` uses four opposing vanilla sticky pistons to close/open a 2x2 quartz door, then checks an obstruction away from the frame, a removed physical frame wall, a shifted frame request, a real entity, invalid top/bottom input and a validated lateral input. A second fixture covers two frame layers without imposing depth-one. It does not run checkpoint protocol #12 or dynamically measure #13. `GeometryChecks` covers pure source interpretation, evidence gaps and rejection behavior; it is not server validation.
